# Source: Taleo Known Bugs — PDF Rejection, Page Expired, Duplicate Applications

## Key Findings

### Bug 1: PDF Resume Upload Rejection
This is the most widely reported Taleo failure mode.

From Reddit r/FinancialCareers (primary user report):
> "I'm applying for a job at taleo.net (linked from the company). I always get 'The file type you selected cannot be uploaded for security reasons' when uploading [my PDF resume]."

From Facebook thread:
> "I have been having so much trouble submitting my application. Every time I try it says my file type for my supporting documentation is wrong."

**Root cause**: Taleo's file security configuration is employer-set. Some employers whitelist only specific MIME types. PDFs generated by certain tools (LaTeX/XeLaTeX, some online converters) may fail MIME-type sniffing even though the file extension is `.pdf`.

**Affected patterns**:
- Large PDFs (> 5MB) — rejected by some Taleo instances with file-size limits
- PDFs with embedded fonts or non-standard metadata — MIME-type mismatch on upload
- Encrypted or password-protected PDFs — always rejected
- `.pdf` files uploaded on instances that whitelist only `.doc`/`.docx` — rejected with "file type" error

**Fallback**: DOCX format is more universally accepted. However, the project currently generates LaTeX PDFs, which are higher risk on Taleo than a clean DOCX.

### Bug 2: "Page Expired" / Back-Button Error
From authoritative industry report ("18% of Taleo ATS Clients Have Broken Back Button Pages"):
> "The technical reason for this broken back button page is that when the candidate clicks back a page it is causing Taleo to do what's called a POST request re-submission."

Taleo's Career Section uses form POST submissions without proper POST-redirect-GET patterns. Clicking the browser back button causes a POST replay which Taleo interprets as a form resubmission, triggering:
- "You may have pressed the back button..." error
- "Page Expired" error
- Application state corruption (fields cleared, progress lost)

This affects **18% of Taleo deployments** based on the industry scan. The agent MUST NOT use browser back navigation on Taleo — it must use only the ATS's own "Previous" / "Back" buttons within the form.

### Bug 3: Duplicate Application Error
From Oracle Taleo documentation:
> "This is an intermittent issue that can happen to a small subset of applications like agency forwarded or referred applications with merged candidate profiles."

If the candidate applies twice (even from different referral sources), Taleo may show a "You have already submitted an application for this requisition" error. This can also happen if the account creation step partially completed but the application was never submitted — Taleo may have created a draft that blocks re-apply.

### Bug 4: Session Timeout During Long Applications
Taleo Enterprise sessions expire after ~20 minutes of inactivity. If the user (or agent) is paused mid-application, the session silently expires. The next action (clicking "Next" or "Save") redirects to the login page. All unsaved form data is lost.

### Bug 5: Required-Field Validation Failures on Edge Cases
Taleo's client-side validation sometimes fails to flag missing required fields until the "Submit" click, then scrolls to the first error. The agent needs to handle this graceful error state.
